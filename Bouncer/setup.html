Local AI setup

Choose In your browser or On this Mac in Bouncer settings. Both use a fixed Gemma 4 E2B text model. Your posts and filter phrases are processed on your device; images and videos are judged by their written text.

Your choice is saved separately from setup. A failed download, unavailable GPU or missing Ollama connection keeps that choice. Bouncer does not switch engines automatically. Manual Bounce and Restore remain available.

In your browser · LiteRT-LM

  1. Choose Use browser AI. If the model is known to be missing, Download & use browser AI combines the choice with an explicitly requested download.
  2. Use Download browser model when needed. About 2 GB is fetched from the fixed Hugging Face source and verified before use. This model-file download is separate from local inference.
  3. The downloaded files stay in this Chrome profile. Ready means the files are available; the GPU model loads only for an actual request. Preparing is GPU initialization, not a download.

If WebGPU is unavailable, check that Chrome supports WebGPU and hardware acceleration is enabled, then choose Retry browser AI. Bouncer does not load the model just to test an option. You can choose Ollama at any time.

Cancel is available during a download or GPU preparation and keeps your choice. Canceling GPU preparation retains the downloaded files and pauses automatic preparation until you click Retry browser AI. Wait for Finishing cancellation to settle before starting another browser operation. Delete downloaded browser model removes only its model files; it keeps your filters and manual decisions. Chrome can also evict stored files. If that happens, a new download requires your explicit action.

Browser files belong to this profile and are separate from Ollama’s installation. Deleting them does not remove an Ollama model. Browser GPU memory is released after idle use; the downloaded files remain.

On this Mac · Ollama

This option uses the existing official Ollama app at http://127.0.0.1:11434. Bouncer checks the exact local model and runtime before sending text. It cannot install a model, configure or start the app, or remove native models.

First-time preparation

  1. Install the qualified Ollama 0.40.3 application and matching CLI. Keep its service bound to loopback and disable Ollama cloud features while preserving the rest of your settings.
  2. Use the Bouncer operator setup guide from a source checkout. It identifies the exact source weights and license, how to acquire them if missing, and how to preserve existing aliases.
  3. With the qualified service running and other local models idle, run this from the Bouncer repository root using a stable Node 24 executable:
node scripts/prepare-native-model.mjs

The script prepares and verifies the text-only alias bouncer-gemma4-e2b-qat-text:v1. It performs no inference or model download. A model with a different name, weights or version does not satisfy this contract.

  1. Choose Use Ollama, then click Connect to Ollama. Allow only the local connection to http://127.0.0.1:11434/*. Bouncer checks metadata without preloading weights. If Chrome closes the popup during the grant, reopen settings to see the current result.

Connection and setup problems

  • Not connected: click Connect. Denying or revoking permission keeps your saved engine choice.
  • Unavailable: open the Ollama app on this Mac, then Retry.
  • Model missing or could not be verified: follow the fixed-model preparation in the operator guide, then Retry. Do not substitute another artifact or upgrade the qualified runtime.
  • Ollama rejected Bouncer’s connection: follow the operator guide’s exact-origin procedure. Preserve other allowed origins and the loopback/cloud-disabled settings. The extension origin is chrome-extension://bkijmhafoocfloemhancbgadknkgdkcm; do not use a wildcard. The documented helper launches the existing app with the finite origin set and verifies metadata. A general health check does not establish Chrome access.
  • Another local model is loaded: let the other client finish and release it, then Retry. Bouncer will not unload another client’s model.

Ollama loads the model for an actual request. It may release it after idle use; other clients sharing the model can keep it resident. Bouncer does not change native retention or scheduling settings.

Previous Ollama request needs recovery

An interrupted request may still be running in Ollama. Automatic inference pauses for either engine until it is settled. Selecting Browser AI, canceling a browser operation, reconnecting or clicking ordinary Retry does not prove that the previous native request stopped.

  1. Let other local clients finish and remain idle.
  2. Use Quit Ollama normally. Confirm the application, server and local listener have stopped.
  3. Reopen through the existing, documented exact-origin startup setup. Follow the operator guide’s controlled --launch --confirm-ollama-stopped procedure; an ordinary launch may not preserve that setup.
  4. If Bouncer needs connection permission, click Connect to Ollama. This does not confirm a restart or change your engine choice.
  5. Click Resume after restarting Ollama and confirm the full restart and idle clients. Bouncer then verifies the service and resumes your selected option.

If the recovery action is unavailable, use a qualified Bouncer build and the operator guide. Bouncer never clears this pause merely because time passed or no resident model is listed.
